# 校园网访问

本次开放地址：**https://100.78.91.204:8443**。访问电脑仍需使用已有 Portal 用户名和密码登录，不需要提供官方 HPC 密码。Mac 必须保持开机、不休眠，并持续运行启动窗口。

## 第一次访问

1. 将本机 `.tools/campus/portal-campus-ca.crt` 这个公开证书文件复制到访问电脑，通过操作系统的证书管理功能手动信任它。Mac 可使用“钥匙串访问”，Windows 可使用当前用户的“受信任的根证书颁发机构”。证书安装或信任确认由使用者本人完成。
2. 在浏览器打开上面的 **HTTPS** 地址，使用自己的 Portal 账号登录。
3. 如果提示证书不受信任，检查是否安装了本次证书；如果超时，检查校园网是否允许电脑之间互访；如果显示 403，向管理员提供访问电脑的实际校园网 IP，以核对允许网段。

目前没有学校域名和公有 CA 证书，使用 Caddy 本地 CA。未信任该 CA 的设备会显示证书错误；这不等于服务器未启动。[Caddy 本地 HTTPS 说明](https://caddyserver.com/docs/automatic-https#local-https)

本次 CA 的 SHA-256 指纹：

    40:EA:9C:40:BE:34:93:93:01:3D:F0:A1:A6:88:B7:E8:88:E5:E2:2B:FD:D3:59:48:A2:64:B7:E0:82:4B:BC:96

只分享上述 `.crt` 公开文件。`.tools/campus/data` 中的根证书私钥、中间证书私钥、站点私钥都保留在 Mac 的受保护目录内。

## 启动与关闭

继续在 Mac 本地终端使用原命令：

```sh
/bin/bash /Users/chenfk1/Projects/Serve/.tools/run-web-terminal.sh
```

启动脚本读取受保护且不进入版本管理的 `.tools/campus/campus.env`，构建前端生产资源、校验 HTTPS 配置，启动本机开发前端、后端与校园网入口。在此终端隐藏输入 HPC 密码，看到 `Application startup complete` 后即可使用。密码仅保存在后端进程内存中，每次重启重新输入。

Ctrl+C 会关闭并回收本次前端、后端和 Caddy 入口；最多等待约 5 秒再结束仍未退出的进程。任一服务启动失败时也关闭其余服务。不会按端口批量结束其他程序。

## 实际开放范围

- Caddy 只在本机校园网 IP `100.78.91.204:8443` 提供 HTTPS，静态文件根目录仅为 `frontend/dist`。
- Uvicorn `127.0.0.1:8000`、Vite `127.0.0.1:5173` 继续只在本机监听。对外页面使用构建后的资源，不暴露 Vite 开发服务或项目源目录。
- 根据本次 `en0` 网卡的实际 IP 和 `255.254.0.0` 掩码，允许子网为 `100.78.0.0/15`。这是实际连接的子网，不代表已确认学校全部校园网网段；其他校内网段需据实补充，不能猜测。
- Caddy 根据连接的真实来源地址检查网段，不接受客户端伪造的 X-Forwarded-For 绕过限制。Caddy 管理接口、HTTP 重定向监听和 HTTP/3 均未开启。
- `/api/*` 和 `/ws/*` 原样代理到本机后端，保留 Origin、Cookie 和 CSRF 校验。校园网启动环境启用 Secure Cookie 并加入实际 HTTPS Origin；后端只信任来自 `127.0.0.1` 代理的来源地址转发头。
- 真实 SSH 的用户授权范围保持原有 test01，不因开放网页而新增官方账号、创建远程目录或扩大真实终端授权。新增成员仍需管理员配置和相应真实 SSH 授权。

浏览、上传和下载仍经过 Mac 转发；不会因为开放校园网而将 HPC 文件整份缓存到 Mac。用户点击下载时，文件保存到该用户正在使用的电脑。

## 配置与维护

实际配置文件是 `.tools/campus/campus.env`，通用网关模板是 `deploy/Caddyfile.campus`，日志是 `.tools/campus/gateway.log`。校园网配置只在启动子进程中生效，没有覆盖根目录 `.env`。CA、证书及私钥存放于 `.tools/campus/data`；脚本不自动更改设备的证书信任库或系统防火墙。

校园网 IP 变化后，需按实际新地址同步 `PORTAL_CAMPUS_IP`、`PORTAL_CAMPUS_CIDR` 和 `PORTAL_ALLOWED_ORIGINS`，再重启；不能继续分发旧地址。保留原 CA 数据时，Caddy 可为新地址签发站点证书，访问设备已有的 CA 信任可继续使用。

恢复仅本机访问：先在启动窗口 Ctrl+C，再将 `.tools/campus/campus.env` 改名保留为 `campus.env.disabled`，重新运行启动脚本。重新启用时恢复该文件名并按实际地址核对配置。

本次仅实现校园网 HTTPS 访问，不包含 launchd、自动唤醒、定时备份、日志轮转或 Phase 4 任务/计费。

## 两台电脑连同一 Wi-Fi 但访问失败

`100.78.91.204` 与 `100.79.75.234` 在掩码 `255.254.0.0` 下同属 `100.78.0.0/15`，均已在当前来源允许范围内，IP 第三段或第二段不同不表示配置错误。同一 SSID 或同一 IP 子网仍可能存在无线设备隔离、其他网络访问控制或浏览器代理，不能仅据 IP 判断互通。

先从访问电脑直接测试 TCP，避开浏览器代理和证书因素。Windows PowerShell：

```powershell
Test-NetConnection 100.78.91.204 -Port 8443
```

Mac 终端：

```sh
nc -vz -G 5 100.78.91.204 8443
```

TCP 成功而浏览器失败时，再核对完整 HTTPS 地址、证书信任和访问电脑的代理设置；代理应对本站 IP 直连。TCP 失败时，继续核对两台设备的当前地址、校园无线设备隔离及主机网络权限。Ping 不通本身不能证明 Wi-Fi 隔离，也不应通过放宽应用来源白名单来掩盖底层网络不通。

## 验证

设置 `PORTAL_TEST_CADDY` 为 Caddy 可执行文件的绝对路径后，运行后端测试会包含真实 TLS 网关测试。该用例使用临时数据库、Mock SSH、动态回环端口和临时 CA；严格校验证书，覆盖生产静态页面、登录和 Secure Cookie、角色权限、Origin/CSRF、转发 IP 防伪、WSS 终端、1 MiB 分块上传下载哈希及来源网段拒绝。

本次后端 63 项、前端 7 项、Chromium 2 条流程及 7 项伪终端生命周期验收通过。实际校园网 IP 的 HTTPS 页面与真实模式健康检查返回 200，未登录 API 返回 401，非法 Origin 返回 403。其他电脑能否经过校园网到达该端口，仍需由另一台设备实测；学校设备隔离无法仅在本机检查中确认。
