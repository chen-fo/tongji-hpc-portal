# Phase 3：个人文件管理

已实现网页个人目录浏览、创建目录、原始字节流上传、流式下载、重命名和删除；同时支持 Mock 与真实 AsyncSSH SFTP。Phase 4 的任务、预算、计费尚未开发。

## 启动与升级

已有 Phase 2 数据库需先备份，再执行迁移。命令在 backend/ 运行：

    uv run python -m app.cli backup-db --output /absolute/path/new-backup.sqlite3
    uv run alembic upgrade head

当前版本为 0003_files，新增 file_audit 表，不改变已有账号映射、密码、终端记录或科研目录。后端需要重启才能加载文件 API；密码认证模式重启后须在本机重新隐藏输入 HPC 密码，仍只存在服务进程内存。

本机 test01 联调可继续使用项目根目录的 `bash .tools/run-web-terminal.sh`，在 Mac 终端隐藏输入 HPC 密码。该脚本同时管理 8000 后端和 5173 前端，按 Ctrl+C 会停止并等待本次两个进程退出，再显示“本次前后端服务已停止”。等待密码时也可用 Ctrl+C 退出；任一服务提前退出会关闭另一个。脚本不会按端口批量杀进程，另行启动的服务需在各自的原窗口停止。

学生使用已绑定的身份登录，侧栏选择“文件”。没有个人目录映射的管理员身份不显示个人文件入口；管理员使用“文件记录”查看成员的网页文件操作。

## 使用方式

- 根目录显示为“个人目录 (~)”，对应服务端已保存的个人工作目录；面包屑和“返回上级”用于导航。
- 文件显示大小与修改时间。上传可一次选择多个文件，按顺序传输，显示当前文件的进度，可取消。
- 上传和重命名遇到同名目标均拒绝覆盖。需要替换时，由用户先重命名旧文件或明确删除，再重新上传。
- 下载使用浏览器原生下载，不在 JavaScript 中构造完整 Blob。进度、保存位置和取消使用浏览器下载列表；目录打包下载未实现。
- 文件夹删除需要确认递归删除。服务端先检查整个有界目录树，再自底向上删除；目录过大或存在软链接时拒绝，不静默跟随链接。
- 空文件可以上传与下载；名称支持 UTF-8。绝对路径、..、空路径段、控制字符、超长路径和不受支持的名称均拒绝。
- 全部软链接和特殊文件显示为受限，首版不跟随链接，即使链接当前仍指向自己的目录。

真实写操作仅对 PORTAL_SSH_WRITE_USERS 中的用户开放；其他已绑定用户可以浏览和下载。用户仍需有服务器本身的文件权限。不会在打开页面时自动创建目录或修改文件。

## 传输与资源边界

数据路径为“浏览器 ↔ Mac 有界内存缓冲 ↔ HPC SFTP”，没有完整文件的本地临时副本。上传采用 Request.stream()，不使用 multipart 临时上传文件；浏览器直接发送 File。下载使用 StreamingResponse，每次读取最多 64 KiB，SFTP 单次并发请求数设为 1。

上传在目标目录内排他创建 .portal-upload-<随机值>.part 文件，完整接收、校验长度并关闭后，通过不覆盖目标的 SFTP rename 保存为最终名称。已知超限、取消或错误会尝试关闭并移除该临时文件；网络断开或父目录被替换时可能留下远端 .part，不会为了清理而跟随不安全路径。客户端取消也可能发生在服务器已经保存之后，应刷新目录核对最终结果。

下载以打开句柄后查得的大小为本次传输长度。文件随后缩短、连接中断或登录失效时，传输会失败；不会把不完整结果记为成功。并发修改的文件不提供快照一致性保证。

配置默认值：

| 配置 | 默认值 |
| --- | --- |
| PORTAL_FILES_MAX_UPLOAD_BYTES | 100 GiB，实际累计字节与 Content-Length 均检查 |
| PORTAL_FILES_MAX_ENTRIES | 5000，限制单次列表及递归删除条目 |
| PORTAL_FILES_MAX_PER_USER | 2 |
| PORTAL_FILES_MAX_PER_ACCOUNT | 4 |
| PORTAL_FILES_MAX_TOTAL | 8 |
| PORTAL_FILES_IDLE_SECONDS | 60，每次网络读取/写入等待上限 |

并发限制目前按后端进程计数，列表等元数据操作也占用名额；超限返回 429，不无限排队。大目录返回截断标志及提示。下载与上传在继续传输时约每秒复查登录状态，上传保存前强制再校验；长时间没有数据的传输按等待超时回收。断点续传、Range、拖拽目录和跨用户共享不在首版。

## 路径与审计

真实 SFTP 连接重新查询官方 HOME 并核对个人目录映射，拒绝沿用 Mock 路径。路径由当前登录用户和数据库映射决定，浏览器不能选择其他用户或官方账号。逐级执行 lstat 和 realpath 检查，新目标验证父目录，禁止删除、移动或重命名个人根目录本身。文件操作不拼接远程 Shell 命令。

这些检查防止路径穿越和检查时存在的软链接越界。共享 Linux UID、开放终端的架构仍无法提供对恶意并发替换目录的绝对防护；提交上传、清理临时文件和递归删除前会重新校验，发现变化就停止。真正的对抗性目录隔离需要服务器侧 chroot、独立用户或同等级限制，不能把当前实现描述成操作系统隔离。

网页文件操作进入独立类型的异步有界审计队列，记录虚拟用户、官方账号、时间、操作、路径、重命名目标、结果和传输字节，不保存文件内容。管理员可按用户、账号、操作、路径和时间分页筛选。审计失败不阻断文件操作；终端/脚本中的文件操作不出现在该记录中。

## 验证

自动化测试覆盖路径穿越、root 保护、软链接、父目录替换、Alice/Bob 隔离、Origin/CSRF、非管理员权限、上传大小限制、取消/撤销后的清理、并发回收、64 KiB 分块及审计故障。回环测试使用真实 AsyncSSH/SFTP 协议，不访问同济 HPC。浏览器测试覆盖创建目录、UTF-8 文件名、上传、原生下载内容校验、不覆盖、重命名、递归删除和管理员文件记录。

Playwright 默认在 18000/15173 启动独立 Mock 服务，使用临时数据库，不占用日常 8000/5173，不读取真实 SSH 凭据。可通过 PORTAL_E2E_API_PORT、PORTAL_E2E_WEB_PORT 指定其他测试端口。

真实 HPC 已在修复 SSH 多地址连接并重启后，以 test01 验证网页个人目录浏览、原有 51 字节测试文件的浏览器原生下载及文件记录入库；真实终端 pwd 返回个人目录，命令和目录记录正确。上传/重命名/删除仍需在专门的新测试子目录中完成真实 CRUD 验收，仅操作本次新建的文件/子目录，保留原有测试文件和科研数据。不自动执行真实 Slurm 操作。
