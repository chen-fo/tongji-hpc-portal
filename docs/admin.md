# 管理员手册（Phase 0–4 初版）

先按 README 执行迁移和 `init-admin`，再使用自己设置的密码登录。初始化入口仅在本地 CLI 中提供，不开放注册、远程初始化或默认管理员密码。

## 忘记网页管理员密码

原密码无法从数据库查回，只保存 Argon2id 哈希。有本机项目和数据库访问权限的管理员，可以在 `backend/` 的本机交互终端执行：

```sh
uv run python -m app.cli reset-admin --username admin
```

按提示隐藏输入新密码两次（12–128 字符），不需要原密码。命令只更新指定的已有管理员，不创建账号，也不修改 HPC 密码；密码不进入命令参数、配置或日志。重置会撤销该管理员全部旧会话，并清除该用户名及本机回环地址的登录失败限流，以便重新登录。服务无需重启。没有有效终端、输入不一致或取消时不会修改密码。

## 官方账号

“官方账号”页面支持新增、编辑、启停和连接检查，最多三个账号。内部别名与真实 SSH 登录名是不同字段。SSH 目标必须在服务端 `PORTAL_SSH_ALLOWED_TARGETS` 中，网页不能修改允许列表。

默认只允许 `mock-a:22`、`mock-b:22`、`mock-c:22`。密钥引用保存引用名称，不保存私钥内容、密码或文件路径；Mock 模式不会读取任何私钥。

检查结果明确区分 Mock 与真实只读检查。真实连接参数通过本机 profile 配置，建议使用 `sync-ssh-account` 同步；参见 [Phase 2 手册](phase2.md)。停用官方账号会阻止连接检查与新用户目录创建，不会删除已绑定成员，也不会影响成员查看自己的 Portal 身份。编辑已绑定账号时，不能改变 SSH 主机、端口或登录用户名；可编辑别名、启用状态与密钥引用。

## 成员管理

1. 在“组内用户”点击“创建用户”。
2. 用户名为 3–32 位，以小写字母开头，后续可使用小写字母、数字、下划线和短横线。
3. 输入 12–128 字符的初始密码，选择启用的官方账号。
4. 服务端通过 SSH 适配器解析 HOME 并确保 `user/<username>` 目录存在，然后保存账号映射。

目录准备失败时不会创建用户。Mock 目录操作是幂等的；若目录已创建但数据库提交失败，目录可能保留，重试会复用。系统不会为回滚而删除科研数据。

用户列表显示状态、账号映射、工作目录与最近登录时间。重置密码会撤销该用户的全部旧会话；停用/归档同样撤销会话，但保留用户、目录和数据。重新启用后必须重新登录。`DELETE /api/admin/users/{id}` 也只执行归档，不进行物理删除。

不能通过 API 或前端直接修改成员用户名、角色、官方账号映射和工作目录。迁移不在本阶段实现。管理员自身密码在“设置”修改，不能通过成员管理停用管理员。

## 文件管理与记录

Phase 3 新增 file_audit 迁移；升级前备份数据库，执行 alembic upgrade head 并重启后端。学生在“文件”页面管理自己的目录，管理员在“文件记录”筛选成员的浏览、上传、下载、目录创建、重命名与删除结果。账号配置不变更，管理员不能通过文件 API 指定其他用户目录。

真实文件写操作复用 PORTAL_SSH_WRITE_USERS 的用户范围；未开放写入时只读浏览和下载。100 GiB 上传上限、文件操作并发与目录条目限制均可配置，参见 [Phase 3 手册](phase3.md)。所有软链接拒绝跟随，同名目标拒绝覆盖。网络故障可能留下远端随机命名的 .portal-upload-*.part，清理前先核实路径和是否仍有传输，不能批量删除科研数据。

## 登录与会话

会话默认 12 小时。退出撤销当前会话；修改自己的密码撤销所有会话并要求重新登录。登录失败达到窗口限制时需等待 15 分钟。后台不会记录密码正文，SQLite 中只保存 Argon2id 密码哈希和 Cookie 的 SHA-256 摘要。

WebSocket 默认每秒复查会话，停用、改密、重置密码和退出后会关闭已有终端。管理员没有官方账号映射时不显示终端入口；请创建并绑定专用 test01 身份验收。

“命令记录”页面可按用户、账号、目录前缀、时间查询。真实模式的已有账号别名也不能修改，因为它绑定本机 profile。审计不保存原始终端输入，不能保证覆盖脚本内部、嵌套 Shell 或主动绕过行为。

## 任务、预算与费用

“任务”页面展示后台只读同步的 Slurm 任务。管理员需根据可靠证据，手动将未归属任务关联到同一官方账号下的成员并填写原因；归属会记录操作者，不可直接覆盖。数据过期或状态待核实表示不能将结果视为完整或最终结果。

在“费用与预算管理”中可设置成员累计预算、提醒阈值和已核实的费率版本，并登记有原因的费用调整。任务符合核算条件后，在任务的“查看费用”中由管理员确认记入；入账时保留任务和费率证据。当前为观察模式，预算不能阻止终端提交作业，也没有网页提交功能或预置学校费率。内部核算不等于学校账单；官方账单差额需填写参考号。详细操作、查询范围及限制见 [Phase 4 说明](phase4.md)。
